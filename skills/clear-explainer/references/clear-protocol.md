# CLEAR protocol

Use this reference for a substantial lesson or a follow-up that needs more than a
single explanation. Select only the representations that serve the request.

## Establish the concept

Identify the question the learner is trying to answer, what they already appear
to know, and any condition that changes the answer. Ask about a prerequisite only
when the response would otherwise depend on an important unknown; otherwise define
it briefly and continue.

Keep a compact internal concept model: essence, mechanism, assumptions,
prerequisites, example, and likely misconception. This is a reasoning aid, not a
required JSON output or a promise of persistent memory.

## Render the same model in useful forms

| Representation | Use it to answer |
| --- | --- |
| Understand | What is happening, and why? |
| Mental model | Which relationships should I picture? |
| Visual | What connects to what, or in which order? |
| Worked example | How does the mechanism act on a concrete case? |
| Deep dive | Which assumptions, derivation, or edge case matter here? |
| Verify | Which claims were checked, and what remains uncertain? |
| Practice or teach-back | Can the learner use or explain the mechanism? |

A diagram must use the same entities and direction of causality as the text.
Describe its structure in text if rendering is unavailable. Offer an interactive
prediction or step-through when useful; do not claim to have built or executed a
widget unless the environment actually supports that work.

## Continue and repair

Use a follow-up to extend or correct the current model. Preserve established terms
and assumptions unless the new question changes them; make that change explicit.
If the learner says they are confused, identify the unclear link rather than
restarting the entire topic automatically.

For teach-back, name one correct relationship and any specific mistaken or missing
relationship. Give a concrete correction and a small retry prompt. An incomplete
answer is evidence about this explanation, not proof of a learner's ability.

For a quiz, ask one question or a short requested set, without an answer key in the
same initial response. After the learner answers or requests the solution, explain
the reasoning and any misconception; do not imply certification or store a score
unless the task and environment explicitly support it.
